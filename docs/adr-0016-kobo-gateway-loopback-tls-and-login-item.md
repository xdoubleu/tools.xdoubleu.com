# ADR-0016: Loopback HTTPS for Safari, and a LaunchAgents plist over `SMAppService`

- Status: Accepted
- Issues: —
- Affects: `kobo-gateway/internal/kobogateway/server.go`, `tls.go`, `loginitem.go`

## Context

Two independent platform constraints shape how the gateway is reached and how it
stays running.

## Decision

### Loopback **HTTPS**, not HTTP

The server listens on `https://127.0.0.1:41132`. **Safari blocks a secure page
from fetching a plain-HTTP loopback URL**, and the books page is always
`https://`. Chrome exempts loopback from that check; Safari does not.

This is what forces the whole self-signed cert apparatus: `EnsureCert` generates
a self-signed ECDSA P-256 cert and `EnsureTrusted` adds it to the login keychain
via `security add-trusted-cert`, prompting the user once. See
`spec-kobo-gateway-runtime.md`.

### A plain LaunchAgents plist, not `SMAppService`

`loginitem.go` manages a plain `~/Library/LaunchAgents` plist. **`SMAppService`
needs macOS 13; this app's minimum is 12.0.**

The plist sets `KeepAlive.SuccessfulExit: false`, so launchd relaunches the
gateway on any abnormal exit — a panic, a listener error, or darwinkit's AppKit
bridge `SIGABRT` — but **not** on a clean Quit (exit 0). This is the outermost
layer of the crash-recovery design, and the only one that covers `SIGABRT`.

`EnsureInitialLoginItem` auto-registers it once on first-ever launch (marker
file); after that only the menu-bar toggle changes it.

`SyncLoginItem` runs on every launch to rewrite an already-enabled plist to the
current template — picking up changes like `KeepAlive` — **without touching
`launchctl`**, since a bootout/bootstrap cycle would kill the very process
calling it. The refreshed policy takes effect on the next login/reboot.

## Alternatives considered

### Plain HTTP on loopback

Rejected: Safari refuses it from an HTTPS page, and the books page is always
HTTPS. Chrome-only support isn't acceptable.

### `SMAppService` for the login item

Rejected: it requires macOS 13 and the app supports 12.0.

### `launchctl bootout`/`bootstrap` to apply plist changes immediately

Rejected: it would kill the process performing the sync. Rewriting the file and
letting the next login pick it up is the only safe order.

## Consequences

- Users get a one-time keychain trust prompt; if Safari still rejects the cert,
  the fallback is the System keychain, which needs sudo.
- A `KeepAlive` policy change doesn't take effect until the next login/reboot.
- The cert is valid 10 years and regenerated by deleting `cert.pem`/`key.pem`.

## Revisit when

The app's minimum macOS version rises to 13, making `SMAppService` available.
